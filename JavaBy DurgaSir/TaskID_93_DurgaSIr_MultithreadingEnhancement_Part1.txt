## ThreadGroup in Java – Real-World Example

ThreadGroup is useful when you need to **manage, monitor, or kill a set of related threads as a unit** — rather than tracking them individually.

---

### Real-World Scenario: Web Crawler / Batch Job Processor

Imagine a system that spawns multiple worker threads per "job" (e.g., crawling a website, processing a batch of files). You want to:
- Monitor all threads in a job together
- Kill all threads of a **specific job** if it times out or errors
- Catch uncaught exceptions from any thread in the group

```java
import java.util.concurrent.atomic.AtomicBoolean;

public class BatchJobProcessor {

    // Custom ThreadGroup that handles uncaught exceptions for the entire group
    static class JobThreadGroup extends ThreadGroup {
        private final String jobId;
        private final AtomicBoolean jobFailed = new AtomicBoolean(false);

        public JobThreadGroup(String jobId) {
            super("Job-" + jobId);
            this.jobId = jobId;
        }

        // Called automatically when ANY thread in this group throws an uncaught exception
        @Override
        public void uncaughtException(Thread t, Throwable e) {
            System.err.println("[Job: " + jobId + "] Thread '" + t.getName()
                    + "' crashed with: " + e.getMessage());

            jobFailed.set(true);

            // Interrupt ALL other threads in this job group immediately
            System.out.println("[Job: " + jobId + "] Cancelling all remaining threads...");
            this.interrupt(); // interrupts every thread in the group
        }

        public boolean hasFailed() {
            return jobFailed.get();
        }
    }

    // Simulated worker: processes a file/URL chunk
    static class WorkerTask implements Runnable {
        private final String taskName;
        private final boolean shouldFail;

        public WorkerTask(String taskName, boolean shouldFail) {
            this.taskName = taskName;
            this.shouldFail = shouldFail;
        }

        @Override
        public void run() {
            try {
                System.out.println("[" + taskName + "] Starting...");
                Thread.sleep(1000); // simulate work

                if (shouldFail) {
                    throw new RuntimeException("Data corruption detected in " + taskName);
                }

                System.out.println("[" + taskName + "] Completed successfully.");
            } catch (InterruptedException e) {
                System.out.println("[" + taskName + "] Was interrupted — stopping early.");
            }
        }
    }

    public static void runJob(String jobId, int workerCount, int failAtWorker) throws InterruptedException {
        JobThreadGroup group = new JobThreadGroup(jobId);

        Thread[] workers = new Thread[workerCount];

        for (int i = 0; i < workerCount; i++) {
            boolean shouldFail = (i == failAtWorker);
            workers[i] = new Thread(group, new WorkerTask("Worker-" + i, shouldFail), "Worker-" + i);
        }

        System.out.println("=== Starting Job: " + jobId + " with " + workerCount + " workers ===");
        for (Thread worker : workers) {
            worker.start();
        }

        // Wait for all threads in the group to finish
        for (Thread worker : workers) {
            worker.join();
        }

        if (group.hasFailed()) {
            System.out.println("=== Job " + jobId + " FAILED ===\n");
        } else {
            System.out.println("=== Job " + jobId + " COMPLETED ===\n");
        }
    }

    public static void main(String[] args) throws InterruptedException {
        runJob("JOB-001", 4, -1);       // All workers succeed
        runJob("JOB-002", 4,  2);       // Worker-2 fails → kills entire group
    }
}
```

---

### Why ThreadGroup is the Better Option Here

| Concern | Without ThreadGroup | With ThreadGroup |
|---|---|---|
| **Catch any thread's exception** | Wrap every `run()` in try/catch individually | One `uncaughtException()` override handles all |
| **Cancel all threads on failure** | Keep a `List<Thread>`, iterate and interrupt manually | `group.interrupt()` — one line |
| **Monitor active threads** | Count manually | `group.activeCount()` built-in |
| **Logical grouping** | Implicit — threads are anonymous | Explicit — group has a name, visible in debuggers/profilers |
| **Nested jobs** | No clean hierarchy | ThreadGroups are hierarchical by design |

---

### When ThreadGroup genuinely shines (real use cases)

- **Batch job engines** — kill all workers of a failed job without touching other jobs
- **Request-scoped thread pools** — group all threads serving one HTTP request for observability
- **Game engines** — group AI threads, physics threads, audio threads separately
- **IDE/plugin systems** — isolate plugin threads so a crashed plugin doesn't take down others

> **Note:** For most day-to-day concurrency, `ExecutorService` is the right tool. ThreadGroup adds value specifically when you need **group-level exception handling** or **bulk cancellation by logical group** — things `ExecutorService` doesn't express as cleanly.
